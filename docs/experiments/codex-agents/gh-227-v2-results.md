# GH-227 v2 최종 측정 결과

12개 과제 실행과 2개 독립 리뷰 수집을 완료했다. 최종 품질은 F/B/R/A/X 양쪽 PASS, Q 양쪽 FAIL이다. **After의 보편적인 토큰 최적화 성공이나 운영 도입 승인을 의미하지 않는다.**

## 비교 범위

Before는 사용자 확정 커밋 `4aa58b8b5cad727372e7dac1dd254099b62243b8`의 저장소 지침 85파일, After는 격리된 C1 혼합 지침 94파일이다. 모델 `gpt-5.6-sol`, reasoning `high`와 과제별 실행 계약을 고정했다. 모델 또는 워크플로우 간 우열 비교가 아니다. 각 과제·군당 표본은 1개이며, After는 운영 저장소에 적용하지 않았다. manifest의 NOT_EVALUATED 표기는 생성 당시의 고정 snapshot 상태로 보존한다.

## 과제별 결과

입력에는 캐시 입력이 포함된다. 감소율은 `(Before−After)/Before`이며 음수는 증가다. 품질은 독립 리뷰의 최종 산출물 판정이다.

| 과제 | Before 입력 | After 입력 | 입력 감소율 | Before / After 품질 |
| --- | ---: | ---: | ---: | --- |
| F | 2,266,171 | 2,723,377 | -20.18% | PASS / PASS |
| B | 16,237,771 | 4,063,841 | 74.97% | PASS / PASS |
| R | 2,049,525 | 4,027,423 | -96.51% | PASS / PASS |
| A | 455,936 | 513,523 | -12.63% | PASS / PASS |
| Q | 693,669 | 582,059 | 16.09% | FAIL / FAIL |
| X | 11,867,053 | 4,884,762 | 58.84% | PASS / PASS |

F=기능 구현, B=버그 수정, R=리팩터링, A=아키텍처 설계, Q=요구사항 분석, X=복합 작업. [전체 수치 CSV](gh-227-v2-results.csv)에는 캐시·비캐시 입력, 출력, reasoning 출력, 시간, 원본 결과 hash가 있다.

| 지표 | Before 합계 | After 합계 | 감소율 |
| --- | ---: | ---: | ---: |
| 입력 | 33,570,125.00 | 16,794,985.00 | 49.97% |
| 캐시 입력 | 32,994,688.00 | 16,300,672.00 | 50.60% |
| 비캐시 입력 | 575,437.00 | 494,313.00 | 14.10% |
| 출력 | 125,234.00 | 115,017.00 | 8.16% |
| 실행 시간(초) | 5,305.78 | 5,401.35 | -1.80% |

합계는 실패한 Q를 포함한 고정 6과제 묶음의 관측값이다. 성공한 동일 품질 작업의 비용 절감률로 해석하지 않는다. B·X가 입력 감소를 주도하지만 F·R·A의 입력은 증가했고 전체 실행 시간은 늘었다. 캐시 입력 비중이 높으므로 총입력 감소를 결제 비용이나 구독 한도 절감으로 환산하지 않는다. reasoning 출력은 출력의 부분집합으로 중복 합산하지 않는다.

## 품질과 증거의 한계

- Q 양쪽은 검증 이후 저장 실패의 rollback·임시 상태 정책을 질문하거나 미확정으로 남기지 않고 확정 요구사항으로 적었다. 국가·지역 원문의 오류·로그 비노출 질문도 누락했다. After의 기존 사용자 이관 질문 개선만으로 이 실패가 해소되지 않는다.
- F Before는 최종 산출물 PASS지만 초기 완료 보고에서 불필요한 원격 최신성 조건으로 BLOCKED를 보고했다. 최초 TASK_FAIL 기록을 보존하며 최종 기능 품질과 보고 정확성을 구분한다.
- R은 양쪽 제품 변경이 같아도 입력량 차이가 컸다. 단일 표본의 탐색·검증 경로 차이를 지침 구조의 인과 효과로 단정할 수 없다.
- 독립 oracle: F 각 7건, B 각 단위 9건·실제 DB 3건, R 각 회귀 35건, X 각 단위 19건·통합 4건 통과. A/Q는 문서 과제로 제품 테스트를 실행하지 않았다.
- 독립 리뷰는 제출 소스·oracle 결과·도구 호출 기록을 확인했다. 리뷰 pack에 보조 전체 회귀/harness/hooks의 원시 결과 본문이 모두 포함되지는 않아, 그 부분은 실행 원장과 자체 보고에 의존한다. 모든 검사를 독립적으로 재실행·확인한 것으로 표현하지 않는다.
- X의 비동기 dispatch·실제 컨테이너 error dispatch·운영 로깅 장애/부하는 미검증이다. After는 빈 route 속성 정규화가 약하고 Before 동시성 테스트에는 대기 timeout이 없다. 현재 고정 계약의 실패는 아니다.

## 측정 원장과 예산

동일 UUID 재개는 중단 이전부터 마지막까지 누적 사용량을 한 번만 포함했다. 원래 실패·중단 원장은 보존했다. 본 과제 12개와 리뷰 2개 이외에 품질 재평가 모델 호출을 추가하지 않았다.

| 구분 | 입력 | 출력 | 시간(초) |
| --- | ---: | ---: | ---: |
| 본 과제 12개 | 50,365,110 | 240,251 | 10,707.130 |
| 독립 리뷰 13 | 3,948,962 | 16,960 | 521.296 |
| 독립 리뷰 14 | 1,142,943 | 11,824 | 337.916 |
| 파일럿 이월 | 1,990,954 | 25,443 | 811.076 |
| 측정 전체 | 57,447,969 | 294,478 | 12,377.419 |

최종 승인 한도는 입력 상한 해제, 출력 320,000, 누적 18,000초, 개별 논리 세션 2,700초다. 측정 전체는 출력·시간 한도 안에 있다. 준비·오케스트레이션·별도 결정적 검증의 토큰은 이 CLI 원장에 포함되지 않으며 정확한 총비용은 UNAVAILABLE이다.

## 중단·보정 이력

시간·출력 예산 확대와 입력 상한 해제는 사용자 승인 후 적용했다. 환경 예외는 승인된 정확한 설정/hash 변화만 허용했다. X Before의 usage-limit 메시지 뒤에는 새 계정 상태 확인 후 동일 UUID를 재개했으며 reset credit을 사용하지 않았다. 리뷰 13은 읽기 전용 검색 문자열을 외부 도구 호출로 오인한 guard 정규식을 수정하고 같은 UUID로 재개했다. 원래 오류는 보존했다.

F oracle의 지정되지 않은 생성자/accessor 제약, X oracle의 지정되지 않은 logger 이름·메시지·표현 형식 제약을 계약의 의미 검증에 맞게 조정했다. X 최종 adapter v3를 양쪽에 동일 적용하고 실패 주입 실행 여부도 확인했다. 제품 코드는 oracle 보정을 위해 수정하지 않았다. 이는 평가 도구 보정이 필요했던 한계이며 최초 실패를 제품 결함 건수로 합산하지 않는다. 상세 이력은 [본 실행 보고서](gh-227-v2-main-report.md)에 남겼다.

읽기 격리는 행동 기록 기반이며 완전한 OS 읽기 sandbox는 아니다. 빌드·Testcontainers용 네트워크의 불투명한 외부 부작용까지 검증할 수는 없다. 모델·환경·캐시·재개와 실행 경로의 영향을 분리한 반복 실험이 아니므로 통계적 유의성이나 일반화된 절감률을 제시하지 않는다.

## 완료 범위

- status: 측정 수집 PASS / 후보 전 과제 품질 FAIL(Q) / 운영 도입 미실행
- issue_number: 227
- task_id: GH-227-INSTRUCTION-ROLLOUT-PHASE4
- design_id: HARNESS-DESIGN-GH-227-002 (운영 적용 승인은 별도)
- changed_files: 최종 결과 Markdown·CSV, TASK와 실행 보고서·계획의 진행 상태
- failed_checks: Q 양쪽 최종 품질 FAIL; 과거 oracle·환경·guard 실패는 이력 보존
- blocked_checks: 운영 도입/PR 준비 검증은 이번 측정 마감 범위 밖. `./harness pr-ready --project-tests`는 이번 문서 마감에서 실행하지 않았으며 PR 준비 완료를 주장하지 않는다.
- assumptions/risks: 단일 표본, 캐시와 실행 경로 영향, 리뷰 pack 증거 한계, 준비 비용 제외
- required_human_decisions: 측정 마감에는 없음. After-v1 도입 및 요구사항 지침 보완·추가 측정은 별도 범위 결정이 필요하다.

이번 결과는 After-v1 후보의 첫 기준점으로 보존한다. B/X의 감소와 F/R/A의 증가, Q 공통 품질 결함을 함께 공개하고 특정 구조가 모든 작업에서 우수하다는 결론은 내리지 않는다. 운영 적용·커밋·push·PR은 수행하지 않았다.

최종 문서 검증: `./harness check`, `npm run hooks:validate`, `git diff --check` PASS. 최초 보존 대상 12파일의 SHA-256 일치와 canonical 결과 14개/gate 및 CSV 12개 행의 결과 hash 일치를 확인했다. 신규 결과 Markdown·CSV의 후행 공백 검사도 통과했다.
