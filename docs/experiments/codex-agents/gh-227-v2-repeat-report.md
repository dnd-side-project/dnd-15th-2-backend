# GH-227 B/X 선택 반복 결과

status: PASS (실험 종합 완료; task2 TASK_FAIL 유지)

추가 8회 모델 수집을 완료했다. 사용자 일시 중지 후 재개 이력과 중단 원장은 보존했다. 최종 X oracle v5를 Run1 양쪽과 반복 네 실행에 동일 적용한 여섯 검증과 독립 감사를 완료했다. 모두 단위19·통합4, 실패·오류·skip0이며 8번 최종 gate는 PASS다.

## 현재 관측

B의 Run1 약 75% 입력 감소는 안정적으로 재현되지 않았다. X는 세 쌍 모두 입력 감소 방향이다. 다만 소표본·선택 편향·환경 차이 때문에 전체 작업의 절감률이나 통계적 확증으로 해석하지 않는다.

## 품질 및 최종 검증 상태

B 독립 oracle는 9개 단위·3개 DB 검사다. 추가1·5·6은 PASS이며 추가2는 기능 oracle PASS와 전체 회귀 미완료를 구분한다. X 독립 oracle는 19개 단위·4개 통합 검사다. 최종 v5의 Run1 두 개·추가3/4/7/8 여섯 결과는 모두 **PASS**다. 이전 판정과 중간 버전 결과는 삭제하지 않으며 최종 동일 oracle 결과로 별도 정리한다.

7번의 일부 필수 명령은 원시 종료 코드를 완전히 관측하지 못했다. 보고·남은 XML·관측된 도구 기록으로 확인되는 범위와 미관측 부분을 구분하며, 모든 명령의 raw exit를 직접 확인했다고 주장하지 않는다. 8번은 수집과 최종 품질 gate PASS다.

## 환경과 검증기 보정의 한계

- 모든 반복 입력은 Run1 frozen source·지침·TASK·prompt와 동일하며 Sol/high를 유지했다. 효과가 컸던 B/X를 골랐다는 선택 편향과 각 군 n=3의 제한을 남긴다.
- 캐시·실행 순서·기존 trust/default effort 예외 및 Sites 캐시 가시성 차이가 있다. 7번에서는 deep-research-work 두 파일 소실로 중단했고 사용자 요청에 따라 정확한 hash/부재 예외 후 같은 UUID를 재개했다. 원인은 UNKNOWN이다.
- 공유 Gradle daemon의 캐시/빌드 쓰기 실패가 관측됐다. 권한 원인 자체는 추론이다. 독립 oracle는 --no-daemon으로 분리하고 실험에서 만든 idle daemon만 식별해 정리했다. 이 절차 차이와 B Run2 After의 환경 영향을 숨기지 않는다.
- X 초기 oracle는 logger 이름·로그 메시지·structured 표현·suppressed 예외를 강제했다. 후속 v4는 durationMs/durationNanos 중 하나를 허용했다. v5는 계약에 지정되지 않은 두 완료 event label을 선택적으로 처리한다. duration의 원값/비음수·필드 개수·민감정보·MDC·예외 동일성 조건을 유지하며 환산/반올림하지 않는다.
- 검증기 형식 충돌로 발생한 과거 실패 수를 제품 결함 수로 해석하지 않는다. 원본/v1~v4 및 중단/오류 원장은 보존하고 모델에게 oracle 피드백을 전달하거나 제출 제품을 수정하지 않았다.
