# GH-227 Q 요구사항 분석 지침 후보

상태: `STATIC_PREPARED_EVALUATION_PENDING`. 격리된 C2 후보이며 원본 지침과 운영 환경에 적용하지 않았다.

## Run1에서 확인한 문제

Run1 Q의 Before·After는 독립 품질 검토에서 모두 FAIL이었다. 사용자에게 확인하지 않은 실패 원자성·부분 상태 정책을 확정 요구사항과 완료 조건으로 기록했고, 민감정보 처리에 필요한 질문을 누락했다. 기존 구현의 트랜잭션 동작을 관찰한 사실은 새로운 제품 요구사항을 승인받은 근거가 아니다.

근거는 비공개 `main-001/quality-reviews/review-14.md`의 Q 사례 두 개다. 이 관측만으로 실패 원인을 C1 지침에 귀속하거나 두 구조의 우열을 단정하지 않는다.

## 변경 후보

대상은 frozen C1의 `docs/harness/TASK_DOCUMENT_ROUTING.md` 사본 한 파일이다. 기존 문서 선택 표는 유지하고 다음 조건부 절만 추가한다.

> **요구사항 분석 시 확인**
>
> 요구사항을 구체화하는 작업에만 적용한다. 중요한 항목은 `CONFIRMED`(사용자 답변·승인 문서의 근거), `ASSUMED`(제안과 가정), `UNKNOWN`(미확정)으로 구분한다. 기존 코드의 동작 관찰은 별도 근거이며 새 요구사항의 승인으로 취급하지 않는다.
>
> 실패 시 결과·부분 저장 또는 중간 상태·민감정보의 입력/출력/로그 처리가 범위에 영향을 주는지 확인한다. 필요한 결정은 묶어 질문하고, 답이 없으면 `UNKNOWN`과 후속 결정 사항으로 남긴다. 이미 확인된 답을 반복 질문하지 않는다. 완료 조건에 가정이나 미확정 결정을 확정 사실처럼 넣지 않는다.

추가 문구는 질문과 근거의 관리 방법을 제시한다. Q 고정 응답표의 구체적인 정답 정책이나 값은 포함하지 않는다. 요구사항 분석 전용 분기이며 B/X 반복 입력과 원본 지침은 변경하지 않았다.

frozen 원본의 해시 일치와 기존 본문 보존을 정적으로 확인했다. 격리 후보의 diff·해시·근거는 비공개 `repeat-001/q-candidate/`에 보관했다.

- 원본 SHA-256: `70a24d180200836ac7e2d0fb6e1050624b08219c3415279695b5ed413c54f278`
- 후보 SHA-256: `bda4e89a25eb3c63734c2b0df1822ed892775add1d7fefc899064d7d782d8176`
- 추가 모델 평가의 승인 범위: B/X 각각 Before·After 2회 추가, 총 8개 작업 세션.
- Q 후보 모델 재평가: **0회. Q GREEN 검증은 실행하지 않았다.**

따라서 Q의 품질 개선·토큰 절감·다른 요구사항 과제로의 일반화 효과는 아직 확인되지 않았다. 기존 문제를 보고 만든 후보이므로 같은 과제 재평가만으로 학습 효과와 지침 효과를 구분하기도 어렵다. 운영 채택이나 추가 Q 평가를 완료한 것으로 표현하지 않는다.
