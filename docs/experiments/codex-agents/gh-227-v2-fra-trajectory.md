## 관측 해석

- F: After 입력은 20.2% 증가했지만 비캐시는 78,395→77,873으로 소폭 감소했다. usage 단계 44→52, 평균 단계 입력은 51,504→52,373으로 유사하다. 입력 증가와 연결되는 관측은 더 많은 단계이며, wrapper 43→51·폴링 20→23·검사 키워드 wrapper 9→12가 함께 나타났다. 전체 출력 bytes는 115,333→118,020으로 비슷하다. 양쪽 모두 중단·동일 UUID 재개가 포함되므로 깨끗한 비중단 비교가 아니다.

- R: After 입력은 96.5% 증가했다. usage 단계 40→61과 평균 단계 입력 51,238→66,023이 함께 증가했다. 출력 bytes 135,774→228,937, 10KB 이상 출력 4→7, 폴링 wrapper 17→34이다. After는 제품 notification 설계·ADR과 retry 검색을 한꺼번에 읽고, 구현/설정/테스트 묶음과 전체 테스트 XML 목록도 크게 읽었다. 더 큰 누적 입력과 더 많은 모델 단계가 함께 관측된다. 검사 키워드 wrapper는 10→9이므로 ‘실제 테스트를 두 배 실행했다’고 해석할 근거는 없다. 비캐시 증가는 19.4%로 총입력 증가보다 작다.

- A: After 입력은 12.6% 증가했지만 비캐시는 54,400→46,963, 도구 출력 bytes는 67,832→34,127, 평균 단계 입력은 37,995→30,207로 감소했다. 대신 usage 단계 12→17, wrapper 11→16으로 증가했다. Before는 Promise.all로 문서 읽기를 묶고 마지막 산출물 읽기를 크게 수행한 반면 After는 라우팅·존재 여부·schema 검색 등 여러 작은 읽기 단계를 거쳤다. 큰 문서 출력 자체가 After 입력 증가 원인이라는 해석은 이 기록과 맞지 않는다.

## 근거와 한계

분석 원장은 비공개 `repeat-001/analysis/fra-trajectory.json`에 canonical rollout SHA-256, JSONL 행 번호, usage 증분, 큰 도구 출력의 호출 좌표를 보존한다. 공개 문서에는 원시 명령과 로그를 복사하지 않는다.

단일 실행의 관측 연관성이다. 지침 변경이 이 차이를 유발했다고 입증하지 않았고 개별 문서별 토큰 기여를 정확히 분해하지 않았다. F 양쪽에는 중단·재개가 포함된다. 출력 bytes는 토큰이 아니며 폴링 횟수는 실제 테스트 재실행 횟수가 아니다.

후속 개선 검토 대상은 독립 읽기의 묶음 처리, 필요한 범위의 출력 제한, 긴 검사 실행의 불필요한 모델 폴링 감소다. 이 변경을 B/X Run 2·3 지침에 적용하지 않으며, 현재는 실행 경로 분석 결과로만 남긴다.
