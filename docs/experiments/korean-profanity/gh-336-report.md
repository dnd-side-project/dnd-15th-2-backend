# GH-336 한국어 욕설 판정 실측 보고서

Issue `#336`. OpenAI moderation이 한국어 욕설을 어떻게 판정하는지 두 가지 입력으로 측정했다. 하나는
이번 작업에서 Claude가 작성한 샘플 132개이고, 다른 하나는 AI Hub 텍스트 윤리검증 데이터에서 뽑은 표본
600개다. 운영 정책 엔진 `FlaggedCategoryPolicyEngine`은 응답의 `flagged`만 보고 `local-rules-v1`에는
등록된 단어가 없으므로, 아래 결과는 지금 운영 판정과 같다.

## 요약

- 특정인을 겨냥한 욕설은 22개 중 18개를 잡았다. 놓친 4개 중 3개는 가족을 모욕하는 표현이다.
- 겨냥하지 않은 욕설은 22개 중 20개를 놓쳤다(90.9%). 잡은 2개는 둘 다 "병신 같다"는 표현이다.
- 우회 표기는 32개 중 31개를 놓쳤다(96.9%). 원래 표기로는 잡히는 문장도 우회 표기로 바꾸면 놓쳤다.
- 정상 문장 56개 중 오탐은 2개다. 둘 다 violence로 표시됐고 욕설과 글자가 겹쳐서 생긴 오탐이 아니다.
- AI Hub 욕설 라벨 문장 300개 중 212개를 놓쳤다(70.7%). 정상 라벨 문장 300개 중 14개는 flagged됐다(4.7%).
- 후보 단어 29개를 지금 규칙 엔진 방식으로 적용하면, 직접 만든 샘플에서는 놓친 욕설이 55개에서 8개로
  줄지만 오탐 후보 묶음의 오탐이 1개에서 9개로 는다. AI Hub 표본에서는 놓친 욕설이 212개에서 204개로만
  준다. AI Hub 욕설 문장은 대부분 변형 철자로 쓰여 있어서 정자형 단어 목록으로는 거의 잡히지 않는다.
- harassment 점수 기준값을 낮춰도 놓침과 오탐을 함께 줄이는 지점이 없다. 기준값 0.05에서도 AI Hub 욕설
  문장의 36.3%를 놓치고 정상 문장의 17.3%를 막는다.

## 관찰

### 놓친 욕설

- 혼잣말형 욕설은 대부분 통과한다. "아 씨발 지갑 놓고 왔다", "이 집 떡볶이 존나 맛있다", "오늘 하루 진짜
  좆같다" 같은 문장의 harassment 점수는 0.000~0.196이었다. OpenAI 분류에는 대상 없는 비속어를 다루는
  카테고리가 없다.
- 가족 모욕 3개(T15~T17)를 모두 놓쳤다. harassment 점수는 0.005~0.339였다.
- 우회 표기는 문장이 특정인을 겨냥해도 놓쳤다. "병신아 그것도 못 하냐"(T03)는 0.739로 잡혔지만
  "병1신아 그것도 못 해?"(E09)는 0.019였다. "ㄱㅅㄲ야 꺼져"는 0.198, "개.새.끼야 꺼져"는 0.340이었다.
  우회 표기 중 잡힌 것은 "씨 발 놈 아 조용히 해"(E16, 0.654) 하나다.

### 오탐

- "껌을 씹다가 혀를 깨물었다"(F16)는 violence 0.350, "친구랑 크게 싸워서 마음이 불편하다"(N19)는
  violence 0.355로 flagged됐다. 지금 정책은 flagged만 보므로 둘 다 BLOCK이 된다.
- 한자어, 띄어쓰기 경계, 원래 뜻으로 쓴 단어(시발점, 병신년, 아저씨 발, 개 새끼, 십팔번 등)는 OpenAI에서
  모두 통과했다.

### flagged 경계

OpenAI는 flagged 기준값을 공개하지 않는다. 이번 측정에서 harassment는 flagged된 최소 점수가 0.398,
flagged되지 않은 최대 점수가 0.340이었다. violence는 각각 0.350과 0.116이었다. 관찰값이며 기준값으로
쓰지 않는다.

### 정규화 영향

NFKC는 한글 호환 자모(`ㅅㅂ`, U+3131 대역)를 조합용 자모(U+1100 대역)로 바꾼다. 운영 Java `Normalizer`도
같은 결과를 낸다는 것을 확인했다. 그래서 운영에서는 사용자가 입력한 것과 다른 코드포인트가 OpenAI로 간다.
정규화로 문장이 바뀐 16개를 바꾸기 전 문장으로도 보냈는데 flagged가 달라진 샘플은 없었고 점수 차이는
최대 0.001이었다.

### 반복 실행

같은 샘플로 두 번 실행했다. flagged가 달라진 샘플은 없었고 가장 높은 카테고리 점수의 차이는 최대
0.025였다. 두 번째 실행 결과는 커밋하지 않았다.

### 욕설 표기

ABUSE 라벨 문장에 IMMORAL_NONE 문장보다 자주 나오는 단어를 세어 보면 변형 철자가 대부분이다. 예를 들어
`련`(년), `샠히`(새끼), `죤나`·`줜나`(존나), `스벌`, `십알`, `줄라`, `ㅅㄲ`, `머가리`가 있다. 직접 만든 샘플의
우회 표기 묶음보다 변형이 다양하다.

## 규칙 v2 범위 제안

### OpenAI 판정에 맡길 범위

- 정자로 쓴 특정인 겨냥 욕설 호칭과 위협. 직접 만든 샘플의 name_calling 14개와 threat 1개를 모두 잡았다.
  다만 AI Hub에서 비난·혐오 등 다른 비윤리 라벨이 함께 붙은 욕설 문장은 68.0%를 놓쳤다. 이 데이터는 변형
  철자가 많아서, 놓친 원인이 철자인지 문장 하나하나 확인하지는 않았다.
- 한자어, 띄어쓰기 경계, 원래 뜻으로 쓴 단어. OpenAI는 이 묶음에서 욕설과 겹치는 글자 때문에 생긴 오탐이
  없었다.

### 적용 시뮬레이션

직접 만든 샘플 132개에 적용한 결과다. `ResourceLocalRuleEngine`과 같은 방법으로 비교했다. 문장과 표현을 NFKC, 소문자 변환, 글자·숫자 외 문자
제거로 접은 뒤 표현이 문장에 들어 있으면 적중으로 본다. 최종 판정은 OpenAI flagged 또는 규칙 적중이다.
접기는 Python으로 재현했고 132개 샘플 모두 Java `Character.isLetterOrDigit` 기준 결과와 같았다.

### 규칙 v2에서 함께 정해야 하는 것

1. 단어 목록 방식의 범위. 후보 단어 29개는 AI Hub ABUSE 문장의 2.7%에만 적중한다. 규칙으로 더 막으려면
   변형 철자를 대량으로 넣어야 하고 변형은 계속 새로 생긴다. 규칙 v2를 알려진 정자형·초성 표기를 막는
   보조 수단으로 한정할지, 한국어 욕설을 학습한 별도 분류기를 둘지 정해야 한다. 별도 분류기는 규칙 v2
   범위 밖이다.
2. 오탐 예외. 접기가 공백을 지우므로 "아저씨 발이"(F05), "수박씨 발라"(F06), "체리 씨 발라내는"(F07)이
   `씨발`에, "옆집 개 새끼들"(F09)이 `개새끼`에 걸린다. 부분 문자열 비교라서 "시발점"(F01), "시발역"(F03),
   자동차 이름 "시발"(F04)이 `시발`에, "병신년"(F02)이 `병신`에 걸린다. 예외 목록이나 단어 경계를 보는
   비교가 필요하다. 이 8개는 규칙 v2 회귀 테스트 입력으로 쓸 수 있다.
3. 남는 우회 표기. 숫자 끼우기(E08~E11), 자모 분리(E29, E30), "c발"(E25), "개같네"(U03)는 후보 표현으로
   잡히지 않는다. 접기는 숫자를 지우지 않는다. 숫자를 지우면 "만 18세 이상" 같은 문장과 충돌하므로 변형
   표기를 표현으로 추가할지, 접기 규칙을 바꿀지 정해야 한다.
4. 혼잣말형 욕설 정책. 이번 측정은 강조형("존나 맛있다")도 막아야 하는 것으로 두었다. 막지 않기로 하면
   `존나`, `졸라`를 후보에서 뺀다. `졸라`는 "허리띠를 졸라 매다" 같은 문장과 충돌할 수 있는데, 이번
   샘플에는 없어 측정하지 않았다.
5. violence 오탐. `FlaggedCategoryPolicyEngine`이 flagged만 보는 한 규칙 v2로는 줄일 수 없다. 카테고리별
   기준값은 정책 엔진 교체 범위다. "harassment 기준값" 표처럼 기준값을 낮추는 것만으로는 놓침과 오탐을
   함께 줄이지 못한다.

## 한계

- 직접 만든 샘플 132개는 Claude가 이번 작업에서 작성했다. 외부 데이터셋과 사용자 콘텐츠는 쓰지 않았고, 실제
  사용 빈도를 근거로 고르지 않았다. 실제 사용자 글의 분포와 길이를 대표하지 않는다.
- AI Hub 데이터는 크라우드워커가 작성한 대화 문장이다. 라벨은 데이터 구축 측의 판단이며 이번 작업에서 다시
  검수하지 않았다.
- `omni-moderation-latest`가 가리키는 모델은 OpenAI가 바꿀 수 있고 응답에 snapshot 이름이 없다. 모델이
  바뀌면 다시 측정해야 한다.
- 텍스트만 측정했다. 이미지·영상은 다루지 않았다.

## 재현 방법

```bash
python3 scripts/experiments/korean-profanity-probe.py \
  --samples docs/experiments/korean-profanity/gh-336-samples.csv \
  --out docs/experiments/korean-profanity/gh-336-results.csv
```

- 키는 환경 변수 `OPENAI_API_KEY`에서 읽고, 없으면 저장소 루트 `.env`의 같은 이름 줄만 읽는다. 키는
  출력하거나 파일에 쓰지 않는다.
- python.org 설치본 Python에서 인증서 검증 오류가 나면 명령 앞에 `SSL_CERT_FILE="$(python3 -m certifi)"`를
  붙인다. 이번 측정도 이 설정으로 실행했다.
- `--dry-run`은 API를 호출하지 않고 샘플 형식과 키 유무만 확인한다.

AI Hub 측정은 데이터를 AI Hub에서 직접 신청해 저장소 밖에 받은 뒤 실행한다. 스크립트는 저장소 안 경로에
AI Hub 데이터를 읽거나 쓰지 않는다.

```bash
LABELS=<저장소 밖>/talksets-train-6.json
OUT=<저장소 밖>/gh336-run
python3 scripts/experiments/korean-profanity-aihub.py sample --labels "$LABELS" --out "$OUT/aihub-samples.csv"
python3 scripts/experiments/korean-profanity-probe.py --samples "$OUT/aihub-samples.csv" --out "$OUT/aihub-results.csv"
python3 scripts/experiments/korean-profanity-aihub.py simulate --labels "$LABELS" --results "$OUT/aihub-results.csv"
```

`sample`의 기본값은 묶음당 300개, 시드 336이다. `simulate --results`에 `gh-336-results.csv`를 넘기면
"적용 시뮬레이션" 표를 다시 계산한다.
