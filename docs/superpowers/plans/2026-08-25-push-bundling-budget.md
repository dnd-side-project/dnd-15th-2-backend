# Push 묶음 발행과 예산 억제 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 같은 종류의 notification을 실제 push 호출에서만 묶고 사용자 단위 일일 예산, 질문글 예약 우선권, 기존 quiet hours와 질문 추천 빈도를 안전하게 적용한다.

**Architecture:** `push_dispatch_group`이 사용자에게 보낼 논리 push 한 건을, member가 개별 notification을, 기존 `notification_delivery`가 기기별 provider 결과를 소유한다. 기존 `PushDeliveryDispatchWorker.dispatchBatch` seam은 유지하되 내부를 group planner/claim/suppression/budget module로 교체하고 FCM 호출은 계속 transaction 밖에서 수행한다.

**Tech Stack:** Java 21, Spring Boot 3.5.16, Spring JDBC, PostgreSQL/PostGIS, Flyway, JUnit 5, AssertJ, Mockito, Testcontainers, FCM HTTP v1

**Spec:** `docs/superpowers/specs/2026-08-25-push-bundling-budget-design.md`

**Status:** Approved for build by `@Byuntil` at `2026-08-25T13:03:45+09:00`

- `notification` 1행=1알림과 콘텐츠 열람 자격은 어떤 push 결과에도 변경하지 않는다.

- provider I/O는 DB transaction 밖에서 실행한다.
- `bundle-window`, `max-delay`, `daily-limit`, `direction-reserved`, `recommendation-min-interval`에는 코드 기본값을 두지 않는다.

```sql
CREATE TABLE push_dispatch_group (
    id                    BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    recipient_id          BIGINT NOT NULL,
    notification_type     VARCHAR(50) NOT NULL,
    aggregation_key       VARCHAR(255) NOT NULL,
    status                VARCHAR(20) NOT NULL,
    window_started_at     TIMESTAMPTZ NOT NULL,
    collect_until         TIMESTAMPTZ NOT NULL,
    policy_expires_at     TIMESTAMPTZ NOT NULL,
    attempt_count         INTEGER NOT NULL DEFAULT 0,
    next_attempt_at       TIMESTAMPTZ NOT NULL,
    budget_local_date     DATE,
    budget_consumed_at    TIMESTAMPTZ,
    first_attempted_at    TIMESTAMPTZ,
    created_at            TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    completed_at          TIMESTAMPTZ,

    CONSTRAINT fk_push_dispatch_group_recipient
        FOREIGN KEY (recipient_id) REFERENCES user_account (id) ON DELETE CASCADE,
    CONSTRAINT uq_push_dispatch_group_aggregation_key UNIQUE (aggregation_key),
    CONSTRAINT ck_push_dispatch_group_type CHECK (notification_type IN (
        'ANSWER_RECEIVED', 'ANSWER_REACTED', 'DIRECTION_POST_RECEIVED',
        'REPORT_RESOLVED', 'QUESTION_PROPOSAL_REVIEWED', 'QUESTION_RECOMMENDED')),
    CONSTRAINT ck_push_dispatch_group_status CHECK (status IN (
        'COLLECTING', 'PENDING', 'PROCESSING', 'FAILED', 'COMPLETED', 'CANCELLED', 'DEAD')),
    CONSTRAINT ck_push_dispatch_group_attempt_count CHECK (attempt_count >= 0),
    CONSTRAINT ck_push_dispatch_group_window
        CHECK (collect_until >= window_started_at AND policy_expires_at >= collect_until),
    CONSTRAINT ck_push_dispatch_group_budget
        CHECK ((budget_local_date IS NULL) = (budget_consumed_at IS NULL)),
    CONSTRAINT ck_push_dispatch_group_first_attempt
        CHECK (first_attempted_at IS NULL OR budget_consumed_at IS NOT NULL),
    CONSTRAINT ck_push_dispatch_group_completed_at CHECK (
        (status IN ('COMPLETED', 'CANCELLED', 'DEAD')) = (completed_at IS NOT NULL))
);

CREATE TABLE push_dispatch_group_member (
    group_id        BIGINT NOT NULL,
    notification_id BIGINT NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    CONSTRAINT pk_push_dispatch_group_member PRIMARY KEY (group_id, notification_id),
    CONSTRAINT fk_push_dispatch_group_member_group
        FOREIGN KEY (group_id) REFERENCES push_dispatch_group (id) ON DELETE CASCADE,
    CONSTRAINT fk_push_dispatch_group_member_notification
        FOREIGN KEY (notification_id) REFERENCES notification (id) ON DELETE RESTRICT
);

CREATE UNIQUE INDEX uq_push_dispatch_group_member_notification

CREATE TABLE push_daily_budget (

    consumed_total    INTEGER NOT NULL DEFAULT 0,

    updated_at        TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
    CONSTRAINT pk_push_daily_budget PRIMARY KEY (user_id, budget_date),
    CONSTRAINT fk_push_daily_budget_user
        FOREIGN KEY (user_id) REFERENCES user_account (id) ON DELETE CASCADE,
    CONSTRAINT ck_push_daily_budget_counts CHECK (
        consumed_total >= 0 AND consumed_general >= 0
        AND consumed_general <= consumed_total)
);

CREATE UNIQUE INDEX uq_push_dispatch_group_collecting
    ON push_dispatch_group (recipient_id, notification_type)
    WHERE status = 'COLLECTING';

CREATE INDEX push_dispatch_group_due_idx
    ON push_dispatch_group (status, next_attempt_at, id)
    WHERE status IN ('COLLECTING', 'PENDING', 'FAILED', 'PROCESSING');

CREATE INDEX push_dispatch_group_recommendation_history_idx
```

```java
public record PushPolicyProperties(

    public PushPolicyProperties {

        requirePositive(maxDelay, "maxDelay");
        requirePositive(recommendationMinInterval, "recommendationMinInterval");
        if (maxDelay.compareTo(bundleWindow) < 0) {
```

- [ ] **Step 5: grouping policy 구현**

- `ANSWER_RECEIVED`, `ANSWER_REACTED` → `WINDOWED`

```java
public Decision decide(BudgetSnapshot snapshot, NotificationType type) {
    if (type == NotificationType.DIRECTION_POST_RECEIVED) {
        return snapshot.consumedTotal() < properties.dailyLimit()
            ? Decision.ALLOW_PRIORITY : Decision.DENY;
    }
    int generalLimit = properties.dailyLimit() - properties.directionReserved();
    return snapshot.consumedGeneral() < generalLimit
        && snapshot.consumedTotal() < properties.dailyLimit()
        ? Decision.ALLOW_GENERAL : Decision.DENY;
}
```

- [ ] **Step 4: SQL adapter 구현**

- ungrouped query는 member가 없고 `notification_delivery.status`가 PENDING/FAILED 또는 lease가
  만료된 PROCESSING인 notification만 `FOR UPDATE OF n SKIP LOCKED`로 고른다.
- recommendation cycle ID는 `notification.outbox_event_id → outbox_event.aggregate_id →
  question_assignment.cycle_id` join에서 scalar로 읽는다.
- grouping advisory lock은 `pg_advisory_xact_lock(hashtextextended(:groupingKey, 0))`를 사용한다.
- due claim은 `COLLECTING`에서 `collect_until <= now`, PENDING/FAILED에서 `next_attempt_at <= now`,
  PROCESSING에서 lease인 `next_attempt_at <= now`만 고른다.
- claim은 `attempt_count + 1`, status PROCESSING, nextAttemptAt=leaseUntil을 한 CTE에서 반영한다.

- [ ] **Step 5: transactional planner/service 구현**

```java
@Transactional
public int collectUngrouped(int limit, Instant at) {
    List<PushGroupingCandidate> candidates = repository.lockUngrouped(limit, at);
    for (PushGroupingCandidate candidate : candidates) {
        repository.acquireGroupingLock(candidate.recipientId(), candidate.type());
        repository.closeExpiredCollecting(candidate.recipientId(), candidate.type(), at);
        PushDispatchGroup group = resolveOrCreate(candidate, at);
        repository.addMember(group.id(), candidate.notificationId(), at);
    }
    return candidates.size();
}
```

cycle/singleton은 결정적 aggregation key upsert 결과를 사용하고 windowed만 열린 group을 조회한다.
