# 위치 수집 게이트

GitHub Issue `#379`(위치기반서비스 운영 배포 전 점검표 작업 B1)가 만든 게이트의 운영
문서다. 위치기반서비스사업 신고가 수리되기 전에는 서버가 실제 사용자 좌표를 받거나 읽지
않도록 막는다.

## 1. 게이트가 막는 것

`qello.location.collection.enabled`가 `false`(기본값)이면 다음 API가 HTTP 503과
`DIR-APP-008 LOCATION_COLLECTION_DISABLED`로 거부한다.

| API | 거부 이유 |
| --- | --- |
| `PUT /api/v1/direction/presence` | 정확 좌표의 유일한 입력 경로다. `active_user_presence`에 쓰지 않는다. |
| `GET /api/v1/direction/preview` | 발신자 좌표를 읽어 후보 수를 계산한다. |
| `POST /api/v1/direction/posts` | 발신자 좌표를 `post_audience.origin_position`에 복사하고 매칭을 요청한다. 같은 멱등키 재요청도 거부한다. |

거부는 서비스 메서드 첫 줄에서 한다. 인증 실패(401)와 요청 형식 오류(400)는 게이트보다
먼저 응답한다. 매칭 worker는 막지 않는다. 게이트가 꺼져 있으면 새 좌표가 들어오지 않기
때문이다.

## 2. 게이트를 켜는 조건

`enabled: true`로 두면 기동 시점에 `LocationCollectionGate`가
`qello.location.collection.lbs-registration-reference`를 검사한다. 값이 없거나 승인 참조로
인정할 수 없으면 **애플리케이션이 기동하지 않는다.** fail-closed다.

참조 값에는 신고 수리 문서 번호나 결재 식별자처럼 추적 가능한 값을 넣는다. 다음 값은
미확인으로 본다.

- 비어 있거나 공백뿐인 값
- `true`, `false`, `yes`, `no`, `y`, `n`, `1`, `0`, `ok`, `done`, `na`, `n/a`, `todo`, `tbd`, `-`
  (대소문자·앞뒤 공백 무시)
- 8자 미만인 값

계정 식별자, 토큰, 서버 주소는 넣지 않는다.

## 3. dev·local 예외

활성 프로필에 `dev` 또는 `local`이 있으면 신고 수리 참조 검사를 생략한다. 두 프로필은
테스트 기기 좌표로 기능을 검증하는 비운영 환경이라 `application-dev.yml`과
`application-local.yml`에서 게이트를 켠다.

별도 플래그가 아니라 프로필로 판단한다. 운영 설정에 플래그가 잘못 들어가도 검사를 건너뛸 수
없게 하기 위해서다. 운영 배포는 `dev`·`local` 프로필을 함께 활성화하지 않는다.

통합 테스트의 `test` 프로필은 예외가 아니다. 테스트 전용 참조 값으로 게이트를 켜서 운영과
같은 검사 경로를 거친다.

## 4. 켜기와 끄기

- 켜기: 신고 수리 후 운영 프로필 설정에 `enabled: true`와 신고 수리 참조를 넣고 재배포한다.
  환경변수로 열지 않고 코드 리뷰를 거친 설정 변경으로만 켠다.
- 끄기: `enabled: false`로 바꾸고 재배포한다. 실행 중 전환은 지원하지 않는다.

## 5. 이 게이트가 하지 않는 것

- 신고 수리 여부를 판단하지 않는다. 참조가 있었다는 사실만 강제한다.
- 이미 저장된 좌표를 지우지 않는다. 파기는 점검표 작업 C6이 다룬다.
- 위치정보 이용 동의를 확인하지 않는다. 점검표 작업 C9가 다룬다.
